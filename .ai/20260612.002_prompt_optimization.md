# Оптимизация промптов классификатора рекламы

**Дата:** 2026-06-12  
**Файлы:** `llm/check_ad_prompt.p1.md`, `llm/check_ad_prompt.p2.md`  
**Контекст:** [[20260612.001_ad_classifier_false_positives]]

---

## Проблемы исходных промптов

### 1. p2.md — дубль system prompt

p2.md (user prompt) содержал полную копию всех правил из p1.md с небольшими расхождениями.
Модель получала две версии одних правил и вынуждена была их согласовывать.
При любом расхождении qwen3 выбирал одну версию непредсказуемо.

Дублирующиеся блоки:
- АЛГОРИТМ Шаг 1.1–1.2, Шаг 2 — в обоих файлах
- РЕКЛАМА Шаг 3 — в обоих файлах, с расхождениями в формулировках
- НЕ РЕКЛАМА — в обоих файлах, с расхождениями
- Формат ответа — в обоих файлах
- Белый список `{{ CHANNELS }}` — в обоих файлах

### 2. Взаимоисключающие правила внутри p2.md

Строка 6: `Никакие другие сигналы не повышают ad_rate` (для белого списка)  
Строка 49: `Если сработало правило из блоков "Реклама" — выставлять рейтинг 0.88`

Второе правило отменяло первое. Строка про 0.88 также противоречила конкретным
ставкам из блока РЕКЛАМА (0.8, 0.9, 1.0).

Правило абсолютного приоритета белого списка дублировалось в p2.md дважды
(строки 6 и 23) в немного разных формулировках.

### 3. Пункты РЕКЛАМА без указания ad_rate

Ряд пунктов в блоке РЕКЛАМА не имел явного значения — модель сама решала, что выставить:
- «открытки, оригинальные поздравления, уникальный контент»
- «приглашения и предложения ограниченные по времени»
- «ссылка на оригинальные поздравления» (дубль предыдущего)
- «розыгрышы призов» (также опечатка)
- «ссылки регистрировать и click.ru» (p1) vs «ссылки c текстом регистрация» + «ссылки на click.ru» (p2) — два разных варианта одного правила

### 4. Правило рекламы внутри блока НЕ РЕКЛАМА

p2.md, строка 47:
```
- ссылка-приглашение на канал вне белого списка — это реклама
```
Правило из блока РЕКЛАМА, размещённое внутри НЕ РЕКЛАМА. При CoT модель могла
получить противоречие прямо в середине рассуждения.

### 5. Захардкоженный список названий каналов

p2.md содержал отдельный список имён (PRANK_TG, АХУ*ТЬ, Баба Зоя и т.д.),
не связанный с `{{ CHANNELS }}`. Требовал ручной синхронизации при добавлении каналов.

### 6. Отсутствие примеров (few-shot)

qwen3 — reasoning-модель. Примеры эффективнее абстрактных правил: модель видит
точное соответствие входа и ожидаемого выхода. Примеров не было совсем.

## Что изменено

### Новая архитектура

| Файл | Роль | Что содержит |
|---|---|---|
| `p1.md` | system prompt | Все правила, дерево решений, примеры, формат |
| `p2.md` | user prompt | Задача + whitelist (1 строка) + данные |

### p1.md — дерево решений вместо набора правил

Заменены разрозненные блоки одним деревом:

```
Шаг 1. Найди все URL в тексте — t.me/ и любые другие https://.
Шаг 2. Есть ли хотя бы один URL вне белого списка?
  НЕТ → ad_rate = 0.0. Стоп.
  ДА  → шаг 3.
Шаг 3. Определи тип:
  - Продажа / казино / ставки / курсы / финансы  → 1.0
  - Розыгрыш с внешней ссылкой, сбор с реквизитами → 0.95
  - Реклама чужого Telegram-канала (вне списка)   → 0.9
  - Внешний не-t.me URL (ya.cc, click.ru, трекер) → 0.9
  - Кликбейт без продаж, продолжение по ссылке    → 0.8
```

Каждая ветка имеет явный `ad_rate`. Нет пунктов без значения.

### p1.md — добавлены 4 few-shot примера

Покрывают все основные кейсы ложных срабатываний и истинных позитивов:

1. Собственная плашка канала → 0.0
2. Перекрёстные ссылки сестринских каналов (оба в whitelist) → 0.0
3. Казино с промокодом и внешней ссылкой → 1.0
4. Реклама приватного Telegram-канала вне белого списка → 0.9

### p2.md — сокращён до 3 строк

```
Классифицируй посты. Белый список каналов: {{ CHANNELS }}
Верни JSON массив — ровно столько элементов, сколько постов. Никакого текста до или после.
{{ content }}
```

### Убрано

- Строка про 0.88 (конфликт со специфическими ставками)
- Повторные блоки АЛГОРИТМ, РЕКЛАМА, НЕ РЕКЛАМА в p2.md
- Захардкоженный список имён каналов
- Ошибочно расположенное правило рекламы внутри НЕ РЕКЛАМА
- Пункты без явного ad_rate (открытки, поздравления — убраны как неопределённые)
- Дублированное правило абсолютного приоритета (было 3 раза, теперь 0 — заменено деревом)

## Следующий шаг

Запустить перепроверку с новыми промптами и моделью qwen3.5:9b:

```powershell
python check_ad.py update --force --limit 20 --think
```

`--think` рекомендуется при первом прогоне — видна цепочка рассуждений модели,
можно убедиться что дерево решений выполняется корректно.
