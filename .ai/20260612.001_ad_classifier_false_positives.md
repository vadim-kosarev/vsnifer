## Проблема №1 (КРИТИЧЕСКАЯ): Собственная подписная плашка банится как реклама

Каждый пост в каналах `mens_mem`, `yGOH2UCOglZiNjNi`, `5wnJFWU8yLZjNTdi`, `LIKEHUMOR`
заканчивается фирменным footer'ом со ссылкой на **сам этот канал**. Это стандартный
брендинг, не реклама.

### Примеры ложных срабатываний

**`mens_mem` — ~190 ложных из 253:**
```
TEXT: Молодец какой
      [👉 Суровые мужские мемчики - подпишись и поделись!](https://t.me/mens_mem)
ad_rate: 0.8
proof:   "Пост содержит призыв подписаться на канал 'mens_mem', который входит
          в белый список и является каналом автора."
```
Модель сама пишет что канал в белом списке, но всё равно выставляет 0.8.

**`yGOH2UCOglZiNjNi` — ~43 ложных из 50:**
```
TEXT: Вооооу😍
      [Собакеч](https://t.me/+yGOH2UCOglZiNjNi)
ad_rate: 0.8
proof:   "Собакеч не в белом списке"  ← неверно, канал есть в CHANNELS
```

**`5wnJFWU8yLZjNTdi` (PRANK_TG) — ~100 ложных из 153:**
```
TEXT: Главное на заправку не заезжать
      [PRANK_TG](https://t.me/+5wnJFWU8yLZjNTdi) 👈 [Подписаться](...)
      👉 [Мы в MAX](https://max.ru/public219724157)
ad_rate: 0.8
proof:   "Пост содержит ссылку из белого списка, но включает плашки-приглашения
          подписаться, что по алгоритму засчитывается как реклама."
```

**Диагноз:** LLM знает что ссылка в белом списке (это прямо написано в `proof_of_ad`),
но слово "Подписаться" в тексте всё равно поднимает `ad_rate` до 0.8. Приоритет
белого списка не работает.

## Проблема №2 (СРЕДНЯЯ): Сестринские каналы одной сети не распознаются

Каналы `АХУ*ТЬ` (`HRom-yzU75JhYzIy`) и `ЕБ*НУТЬСЯ` (`otRtx2aMM0ZlMTVi`) — одна сеть,
они кросс-ссылаются друг на друга. Оба присутствуют в `CHANNELS` (белый список).

```
# HRom-yzU75JhYzIy / 21411 — ad_rate=0.9
TEXT: [АХУ*ТЬ](https://t.me/+HRom-yzU75JhYzIy) 👈
      [ЕБ*НУТЬСЯ](https://t.me/+otRtx2aMM0ZlMTVi) 👈
      Доброе 🖐
proof: "ссылки на каналы вне белого списка, в том числе приватную ссылку"
→ Оба канала В белом списке. Ошибка модели.
```

Аналогичная ситуация повторяется в ~11 постах `otRtx2aMM0ZlMTVi`.

## Проблема №4 (МОДЕЛЬНАЯ): `qwen3.5:4b` не держит приоритет правил

Оба промпта явно содержат:
> "Белый список имеет приоритет над любыми другими сигналами."

Но десятки `proof_of_ad` буквально пишут одно, а `ad_rate` выставляется обратное.
Это предел 4B-модели, а не баг промпта.

В `.env` стоит `OLLAMA_MODEL=qwen3.5:4b`, хотя README описывает дефолт `qwen3.5:9b`.

## Рекомендации

### 1. Сменить модель (наибольший эффект)
В `.env` изменить:
```dotenv
OLLAMA_MODEL=qwen3.5:9b
```
9B-модель значительно лучше удерживает приоритет правил при конфликте сигналов.

### 2. Исправить опечатку в промпте
`llm/check_ad_prompt.p2.md`, строка 14:
```
- "PRUNK_TG | Зверолаш"  →  - "PRANK_TG | Зверолаш"
```

### 3. Добавить явное правило в промпт
В блок "НЕ РЕКЛАМА" обоих промптов добавить:
> "Если единственная(ые) ссылка(и) в посте ведут на каналы из белого списка —
> ad_rate = 0.0, независимо от наличия слов 'подпишись', 'поделись', 'переходи'."

### 4. Предфильтр в коде (устранит проблему №1 полностью)
В `check_ad.py` перед отправкой в LLM проверять: если в тексте поста нет ссылок
за пределами `CHANNELS` — сразу писать `ad_rate = 0.0`, не вызывать Ollama.
Это сэкономит ~40% вызовов и уберёт все ложные срабатывания на собственные footer'ы.

### 5. Перепроверить после исправлений
```powershell
python check_ad.py update --force --last-days 30
```

## Выполненные исправления (2026-06-12)

Все 4 исправления реализованы и проверены.

### Fix 1 — Модель `qwen3.5:4b` → `qwen3.5:9b`

Файл: `.env`, строка `OLLAMA_MODEL`.

### Fix 2 — Опечатка в промпте

Файл: `llm/check_ad_prompt.p2.md`.  
`"PRUNK_TG | Зверолаш"` исправлено на `"PRANK_TG | Зверолаш"`.

### Fix 3 — Усиление приоритета белого списка в промптах

Оба файла — `llm/check_ad_prompt.p1.md` и `llm/check_ad_prompt.p2.md`.

Изменения:
- В Шаг 2 добавлено: ссылка из белого списка — **НЕ является рекламным сигналом**.
- Добавлено явное правило в обоих промптах:  
  > **ПРАВИЛО АБСОЛЮТНОГО ПРИОРИТЕТА:** Если ВСЕ ссылки поста входят в белый список → ad_rate = 0.0. Слова «подпишись», «поделись», «переходи» рядом со ссылками из белого списка — НЕ рекламные сигналы, игнорировать.
- В блоке "НЕ РЕКЛАМА" p2.md: строка "Пост содержит ссылку на чужой канал из белого списка" переформулирована в "Пост содержит ссылки только на каналы из белого списка → ad_rate = 0.0."

### Fix 4 — Предфильтр в `check_ad.py`

Добавлены две функции и логика в `cmd_update`:

**`_parse_whitelist_ids(channels_str)`** — разбирает `CHANNELS` из `.env` в `set[str]`
из идентификаторов (`@username` → `username`, `https://t.me/+HASH` → `+hash`).

**`_has_only_whitelisted_links(content, whitelist_ids)`** — возвращает `True`, если все
URL в тексте поста ведут на каналы из белого списка или на `max.ru`. Посты без URL
возвращают `False` и уходят в LLM (могут содержать текстовые рекламные сигналы).

**Логика в `cmd_update`:** перед батчингом посты разделяются на два списка:
- `auto_clear` — только whitelisted ссылки → `ad_rate=0.0` записывается сразу, LLM не вызывается.
- `to_classify` — есть внешние ссылки → идут в LLM как раньше.

`--limit` применяется только к `to_classify`. `--dry-run` показывает оба списка раздельно.

**Результат проверки на реальных данных (`mens_mem`, 679 постов):**

```
Pre-filter: 604 post(s) have only whitelisted links → ad_rate=0.0 (skipping LLM)
LLM queue: 75 post(s)
```

604 поста с footer `[👉 Суровые мужские мемчики](https://t.me/mens_mem)` больше
не попадают в LLM. Аналогично для всех остальных каналов с собственными плашками.
